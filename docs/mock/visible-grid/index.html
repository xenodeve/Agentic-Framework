01

ปัญหา

ไม่ใช่แค่รวม prompt — เป็นเลเยอร์ปฏิบัติการสำหรับ repo ที่ agent คือ developer หลัก ปัญหา 4 ข้อที่วนกลับมาทุกครั้ง:

01.1คนต้องนั่งอยู่ตรงกลาง

มนุษย์ในตำแหน่งกลาง

รัน AI หลายตัวทีละที แล้วคุณก็อยู่กลางคำตอบทุกครั้ง master รับงานครั้งเดียว เลือก skills เอง และ dispatch — คุณ approve เฉพาะช่วงที่สำคัญ

01.2ถามครั้งเดียว · โมเดลเดียว

ถามครั้งเดียว · โมเดลเดียว

โมเดลเดียวถามครั้งเดียวข้าม edge case ไป clink-brainstorm รันหลาย agent หลายมุมมอง พร้อม challenge loop ก่อนลงข้อสรุป

01.3ความลืมของ context

ความลืมของ context

compaction คงแค่ข้อสรุป เหตุผลหายหมด ชั้น memory, ledger และ handoff ทำให้ agent ตัวใหม่เปิดเฉพาะส่วนที่เกี่ยวข้องได้

01.4เขียนไว้ ≠ บังคับได้

เขียนไว้ ≠ บังคับได้

กฎที่ไม่มี check ที่รันได้คือข้อบกพร่องของระบบ ไม่ใช่แค่ของ agent ถ้ากฎสำคัญตรวจสอบไม่ได้ จะถูกบันทึกไว้ว่าเป็นช่องว่าง
