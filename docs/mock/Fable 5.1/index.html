Problem

สี่ปัญหาที่เกิดขึ้นจริง ก่อนจะมีชั้นนี้

architecture ทั้งหมดด้านล่างเกิดจาก session ที่พัง ไม่ใช่ diagram ที่ออกแบบในสุญญากาศ — เลข §3.x ชี้กลับไป brief ต้นทาง

brief §3.1

Human-AI communication bottleneck

ให้ AI หลายตัวช่วยออกแบบทีละตัว developer ต้องอยู่ตรงกลางตลอด อ่าน สรุป ตอบซ้ำ

mechanismmaster agent รับโจทย์ครั้งเดียว เลือก skill กระจายงาน มนุษย์อนุมัติเฉพาะจุดสำคัญ
brief §3.2

Model bias และ single-shot limitation

ถามโมเดลเดียวครั้งเดียว พลาด edge case, compatibility และ assumption ที่ไม่ได้ตรวจ

mechanismclink-brainstorm — หลาย agent หลาย lens challenge loop ก่อนสรุป
brief §3.3

Context amnesia และ workflow drift

session จบหรือ compact แล้ว agent จำได้แค่ข้อสรุป ลืมเหตุผล หลักฐาน และคำถามที่ปิดไปแล้ว

mechanismmemory layer, ledger, records, handoff — เปิดกลับไปเฉพาะ slice ที่เกี่ยว
brief §3.4

Enforcement theater

กฎใน prompt หรือเอกสารถูกข้ามได้ ถ้าไม่มี hook, guard, test หรือ CI ตรวจจริง

Hooks & enforcement

บันไดการบังคับใช้ และขั้นที่ hook ขึ้นไม่ถึง

Prompts guide. Hooks enforce checkable actions. CI protects the shared branch. Humans own the judgment boundary.

LevelMechanismWhat it does

HardPreToolUse · t4-gateblock PR ที่ไม่มี issue, git reset --hard, force push, branch deletion, git clean -f, merge ก่อน verify/review, GitHub mutation ผ่าน MCP

What hooks cannot see

  • คุณภาพของ judgment
  • ความลึกของ review หรือว่า TDD ทำจริง
  • local hook ถูก bypass ด้วย --no-verify
  • regex ไม่ใช่ shell parser — nested command บางรูปแบบหลุด
  • “rule ถูกทำตามไหม” ไม่มี hook ใดตรวจได้ — วัดได้แค่ denominator

Documented ≠ enforced. กฎสำคัญที่ไม่มี executable check คือ defect ของระบบ ไม่ใช่ความผิดของ agent

karpathy-guidelines

คิดก่อนเขียน ทำให้ง่าย แก้เฉพาะจุด และ verify ตาม goal

Problem
ไฟล์ .pyc สองไฟล์ขี่อยู่บน branch ราว 20 commits เพราะ importlib cache ไว้ข้าง source — ไม่มีใน edit/plan/test ใด เห็นแค่ใน git status ที่ถูกอ่านผิดเป็น “ไฟล์ที่ฉันแก้” และอีกเคส agent เติม entry ที่ไม่ได้ขอ แล้ว “เปิดเผย” ใน PR body ราวกับได้รับอนุญาต
Attempt
เพิ่มกฎ “เห็นอะไรไม่ครบ ให้บอก ไม่ต้องทำให้ครบ”, ทุกไฟล์ที่ stage ต้อง trace กลับไปยัง request, และเตือนว่า git add -A stage สิ่งที่ tool เขียนเท่ากับสิ่งที่ user เขียน
Effectiveness
ไฟล์ยอมรับเองว่ากฎยังไม่สมบูรณ์ — incident ถูกกำกับว่า “Measured” แต่ไม่มีวันที่และไม่มี denominator กลไกเก็บหลักฐานต่อคือ skill-feedback issue ท้ายทุก session
